## Task 1 — URL pattern confirmation (discovery, pre-code)

Confirmed empirically with `curl` + browser UA + `Accept-Language: es-MX`:

- `https://mx.computrabajo.com/trabajo-de-{kw}-en-teletrabajo` → **HTTP 200, server-rendered**, 20 `article.box_offer` cards/page.
- Pagination: `?p=N`.
- A leading `.` in a keyword (`.net`) triggers a `301` to the dotless slug → parser normalizes keywords to the dotless form up front.
- **Card structure (verified live):**
  - Card: `article.box_offer` with `data-id`.
  - Title/url: `h2 a.js-o-link[href^="/ofertas-de-trabajo/"]`.
  - Company: `a[offer-grid-article-company-url]`.
  - Geographic location: plain `span.mr10` (e.g. "Mérida, Yucatán").
  - **Work modality** (Remoto/Teletrabajo): a SEPARATE `span` marked by an `i_home` icon.
  - Company rating noise: `span.fx_none.mr10` (e.g. "4.3") — excluded.

**Key design validation:** the geographic span alone (e.g. "Mérida, Yucatán") does NOT
contain a remote keyword, and `scan.mjs` `location_filter` requires an `allow`
substring match. The parser therefore emits BOTH geo and modality
(`"Mérida, Yucatán · Remoto"`) so remote jobs survive downstream filtering, and
`Teletrabajo` was added to `location_filter.allow`.

SSR stop-rule NOT triggered — pages are server-rendered; no JS rendering required.

## Deviations from design

- None material. The design said "extract location from the card's location node";
  empirically that is two nodes (geo + modality). The parser captures both and
  joins them, which fulfills the design's explicit intent that remote labels
  survive `location_filter`. Added a rating-noise guard not anticipated by the
  spec (TRIANGULATE finding).
- Version pinned to `^7.1.0` (matches npm-resolved 7.1.0) instead of the spec's
  unversioned mention.
